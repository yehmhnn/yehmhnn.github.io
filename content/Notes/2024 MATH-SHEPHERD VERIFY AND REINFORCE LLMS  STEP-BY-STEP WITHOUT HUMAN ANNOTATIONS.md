# Abstract
What are the main takeaways, answers to research questions, or new findings?

- Present an innovative process-oriented math process reward model called MATH-SHEPHERD
- Explore the effectiveness of MATH-SHEPHERD in two scenarios: 
	1) Verification: MATH-SHEPHERD is utilized for reranking multiple outputs generated by Large Language Models (LLMs)
	2) Reinforcement Learning: MATH-SHEPHERD is employed to reinforce LLMs with step-by-step Proximal Policy Optimization (PPO).

# 1. Motivation
What problem does the paper address and why is it important?

Even the most advanced LLMs face challenges in complex multi-step mathematical reasoning problems

# 2. Related Work

4 general strategies used in the field to improve the mathematical performance of LLMs
- pretraining
	- Instead of generic internet text, models are fed LaTeX papers from ArXiv, mathematical textbooks, and code repositories (like Python scripts using `numpy` or `sympy`).
- fine-tuning
	- Also called **Supervised Fine-Tuning (SFT)**. Once a model has math knowledge, it needs to learn how to solve problems in a structured way. Researchers use thousands of high-quality examples consisting of a `Question` → `Step-by-step Reasoning` → `Final Answer`.
- prompting
	- This method doesn't change the model’s weights. Instead, it changes the **input prompt** to "unlock" the model's latent reasoning.
- verification
	- Instead of just accepting whatever the model outputs, a separate model (the **Verifier** or **Reward Model**) scores the output.

verification has recently emerged as a favored method
- The motivation behind verification is that relying solely on the top-1 result may not always produce reliable outcomes. A verification model can rerank candidate responses, ensuring higher accuracy and consistency in the outputs of LLMs. 
- In addition, a good verification model can also offer invaluable feedback for further improvement of LLMs

## 3.3. Automatic Process Annotation

Def: 
The quality of a reasoning step is its potential to deduce the correct answer.

-> They aren't training the model to be "mathematically elegant"; they are training it to maximize the probability of being correct. By defining "quality" this way, they can stop relying on humans to check for math logic and instead let the computer check for "winnability."

Solution:
- Completion
- Estimation
	- hard
	- soft
- train PRM with the [[Cross-Entropy Loss]]

| **Feature** | **Generator**                        | **Completer**                                                     |
| ----------- | ------------------------------------ | ----------------------------------------------------------------- |
| **Input**   | Just the Question.                   | Question + a partial path ($s_1, \dots, s_i$).                    |
| **Output**  | One single "draft" solution.         | $N$ different "rollouts" to see if the path is winnable.          |
| **Purpose** | To provide raw text for us to grade. | To provide the **statistical evidence** needed to assign a grade. |
| **Analogy** | A student taking a practice test.    | A simulator checking if a specific move in a game leads to a win. |
Generator and Completer are identical at the start of the "Automatic Annotation" phase. The only difference is at what point in the text they start generating tokens.

## 3.4. Verification

the final prediction answer based on N candidate solutions is:
$$a_{sc+rm} = \arg \max_a \sum_{i=1}^N \mathbb{1}(a_i = a) \cdot RM(p, S_i)$$

| **Symbol**            | **Name**            | **Meaning**                                                                                                                                                     |
| --------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| $a_{sc+rm}$           | Final Prediction    | The final answer the system ultimately outputs.                                                                                                                 |
| $\arg \max_a$         | Argument of the Max | "Find the answer ($a$) that gives us the highest total sum."                                                                                                    |
| $\sum_{i=1}^N$        | Summation           | Look at every one of the $N$ generated solutions ($i=1$ to $N$).                                                                                                |
| $\mathbb{1}(a_i = a)$ | Indicator Function  | A filter: It is **1** if the $i$-th solution arrived at answer $a$, and **0** if it arrived at a different answer. This groups solutions by their final answer. |
| $RM(p, S_i)$          | Reward Score        | The "grade" the PRM gave to that specific solution path.<br>$$RM(p, S_i) = \min(score_{step1}, score_{step2}, \dots, score_{stepK})$$                           |

## 3.5. Reinforcement Learning




The workflow with models placed in the proper positions:

```
Stage 1: Prepare math LLMs

Pre-trained LLMs:
- LLaMA2-7B / 13B / 70B
- LLemma-7B / 34B
- Mistral-7B
- DeepSeek-67B

→ fine-tune generator and completer on MetaMATH for 3 epochs
→ obtain math-capable generators and completers
```

```
Stage 2: Build PRM training data

- **Drafting:** Generators (7B/13B from Stage 1) produce **15 diverse solutions per problem**.
    
- **Goal:** Capture both correct logic and common mistakes for the PRM to learn from.
    
- **Step Annotation:** Completer (**LLemma-7B**) takes each step and "rolls out" $N=8$ completions.
    
- **Labeling:** Finalize labels via Hard Estimation (Success/Failure tokens).

```

```
Stage 3: Train MATH-SHEPHERD

Input:
- question
- step-wise solution
- automatic step labels

→ train PRM / MATH-SHEPHERD

Reward model backbones used in different settings:
- LLaMA2-70B reward model for GSM8K verification
- LLemma-34B reward model for MATH verification
- Mistral-7B reward model for reinforcement learning
```

```
Stage 4A: Use MATH-SHEPHERD for verification

Test question
→ evaluation generator produces 256 candidate solutions

Evaluation generators include:
- LLaMA2-70B Mammoth / WizardMath / MetaMATH
- LLemma-34B MetaMATH
- DeepSeek-67B MetaMATH

→ MATH-SHEPHERD scores each solution step by step
→ convert step scores into one solution score
   usually by taking the minimum step score
→ select the best answer
```

```
Stage 4B: Use MATH-SHEPHERD for reinforcement learning

Policy generators:
- LLaMA2-7B
- Mistral-7B

→ policy generator produces step-wise solution
→ Mistral-7B-MATH-SHEPHERD gives step-level rewards
→ PPO updates the generator

Comparison reward model:
- Mistral-7B-ORM gives outcome-level rewards
```
